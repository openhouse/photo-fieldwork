# Revision D implementation note

Revision D turns lessons from a private whole-library production run into reusable product behavior without publishing the run's photographs, manifests, people associations, paths, or catalog identifiers.

## Implemented

- deterministic capacity-flow assignment for overlapping view eligibility;
- actionable quota infeasibility diagnostics;
- exact source membership digests rather than count-only identity;
- plan, master, and per-album membership digests;
- writer receipts bound to the exact plan digest;
- before-and-after source digest checks in the Apple Photos helper;
- private, validated local profiles;
- whole-visible-library inventory support with minimized retrieval and debug profiles;
- sharded, resumable local inspection and verified recombination;
- corrupt-preview detection and preview-integrity failure reporting;
- explicit fresh-inspection and prior-selection fields and floors;
- hard-negative visual feedback application;
- evaluation denominators, Wilson intervals, small-sample warnings, and per-view gates;
- separated category-fit, safety, public-suitability, and provenance decisions;
- static offline review workspace with CSV feedback export;
- version comparison reports;
- public-safe visual corroboration handoff with prohibited-field checks;
- synthetic tests, Swift type checking, JSON checks, and public-repository privacy scanning.

## Preserved boundaries

The revision does not add cloud analysis, face identification, sensitive-trait inference, direct Photos database writes, automated publication approval, aesthetic ranking across unrelated photographs, or project claims inferred from pixels alone.

## Later work

Potential later releases may add bounded People-to-context sequence retrieval, multi-reviewer disagreement reports, explicit local-derivative cleanup tooling, retrieval benchmarks and FTS, editor comparison sheets, and adapters for other catalogs. Those features should retain the same source-identity, safety, provenance, and publication boundaries.
