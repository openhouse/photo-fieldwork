# Recursive eval hill climb

This revision turns fieldwork failures observed across the parallel revision family into a permanent synthetic eval bank. The cases contain no photographs, private metadata, local identifiers, or run receipts.

## Contract iterations

| Iteration | Cases passing | Failure signal | Change retained |
| --- | ---: | --- | --- |
| Untouched Revision N | 1/8 | Quota drift, silent infeasibility, aggregate masking, duplicate judgments, sample drift, evidence reuse, unbound planning | Initial adversarial bank |
| First correction | 8/8 | Initial cases passed | Exact capacity assignment, per-view gates, sample identity, novel-only rounds, editor-field release binding |
| Expanded bank | 8/12 | Unknown views, duplicate inventory IDs, omitted safety review, and implicit waivers remained weak | Four new permanent cases |
| Second correction | 12/12 | Expanded cases passed | Fail-loud taxonomy, unique source identity, fail-closed safety feedback, explicit waiver lineage |
| Production-shaped expansion | 13/13 | Scale behavior added | 8,000 exact assignments across five overlapping views |
| Skill comparison expansion | 13/14 | Whole-library answers preserved count but not exact source membership | Sorted-UUID source membership fingerprint added to inventory and skill contract |
| Final deterministic bank | 14/14 | Expanded cases passed | Source substitution with an unchanged count is now detectable |

## Scale check

On the same local machine and synthetic 6,000-candidate / 4,000-selection fixture, the first exact min-cost implementation took 70.625 seconds. Replacing it with deterministic capacity-aware maximum flow produced the same exact 800-per-view contract in 0.109 seconds. A subsequent 12,000-candidate / 8,000-selection fixture completed in 0.276 seconds with five exact 1,600-item quotas.

These timings are implementation-development observations, not portable performance promises or CI thresholds. The durable eval is exact production-shaped behavior; speed remains a benchmark to monitor without making wall-clock-sensitive tests flaky.

## Evaluation boundary

The deterministic contracts test software behavior. The prompt bank tests whether an agent using the skill notices when it must stop, widen retrieval, preserve uncertainty, or keep publication closed. Neither can replace fresh visual inspection, archive-owner judgment, consent, provenance research, a ten-item Photos write test, or independent verification of a real run.

## Candidate versus previous skill

Three prompt cases were run against the untouched Revision N skill snapshot and the revised skill with the same synthetic facts.

- **Weak view / contaminated recursion:** the prior skill correctly failed the run but allowed a predominantly fresh round and did not require the sample hash. The revised skill required a failing per-view gate, zero prior UUID overlap, sample-hash verification, and retrieval expansion when fresh evidence was insufficient.
- **Whole-library field:** the prior skill had strong test-first and independent-verification behavior but did not bind recursive freshness or the evaluation sample as executable gates. The revised answer did. The comparison then exposed the missing source-membership fingerprint, which became the fourteenth deterministic case and a new inventory contract.
- **Public handoff:** both versions kept unresolved rights, consent, claims, and collaborator approval closed. This case is not useful for ranking the two versions, but remains valuable as a non-regression safety boundary.
