# Preferred composite B

Revision B remains the integration spine because it already connects a frozen source, explicit assignments, scoped evaluation, safety holds, membership-only plans, receipts, independent verification, and a minimized public boundary. The composite adds the strongest compatible contracts from the parallel `feature/revision-*` family without merging mutually inconsistent implementations.

## Integrated strengths

| Family strength | Composite implementation |
| --- | --- |
| A and N: exact, production-shaped assignment | Exact per-view quotas fail with structured deficits; aggregate count cannot mask scarcity. |
| C and J: durable decision history | Locked run-state revisions feed an append-only hash-linked event ledger. |
| D and H: adversarial eval structure | A 24-case decision bank has explicit oracles, required dimensions, anti-shortcuts, counterfactual pass conditions, and two positive controls. |
| E and I: scoped epistemic states | Editor-field completion and publication readiness remain independently testable release outcomes. |
| F and M: relational safety and artifact integrity | HOLD propagates through connected duplicate and burst relations; plans bind complete evaluation and validation artifacts by canonical digest. |
| G: image-view accountability | Retrieval hypotheses remain separate from explicit inspected assignments and per-view release gates. |
| K: proved holdout independence | A local auditor rejects canonical UUID and perceptual, duplicate, or burst leakage while minimizing public output. |
| L: protected lineage and public closure | Prior outputs, private review structures, and public derivatives remain separate from source evidence and publication authority. |

## Deliberate choices

- The selector does not infer an image's editorial view from overlapping metadata. Revision B requires an inspected, reasoned `assigned_view`; automation ranks within that decision.
- Exact quota scarcity is a useful failure, not permission to coerce an unsupported photograph into a project claim.
- The event ledger records operational truth. It does not replace app receipts or independent catalog verification.
- Synthetic evals can prove software and instruction contracts. They cannot prove visual quality, consent, rights, factual captions, collective credit, or publication approval.

## Release contract

A production write is eligible only when the same source, configuration, proposal, master, evaluation, validation, plan, helper contract, receipts, and independent verification agree. The final publication edit remains a separate purpose-specific human decision.
